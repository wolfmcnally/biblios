# infra/ — the CDK app for the qualification environment

An isolated Python CDK v2 app that synthesizes two stack sets and deploys nothing by itself: the private qualification shape (`biblios-qual-network`, `-artifacts`, `-boundary`, `-custody`, `-instance`, deployed in that order and destroyed in reverse; the boundary stack writes the run-specific permissions boundary from the artifacts stack's real bucket name, so CDK owns the whole lifecycle) and the low-security example (`biblios-example-network`, `-instance`). Every stack uses the bootstrapless synthesizer, takes `RunId` and tags every resource with it, and takes every account-specific value as a parameter; no account, region, image or resource identifier is committed. `CDK_OUTDIR` must point outside the repository.

The toolchain is pinned three ways and never taken from `PATH`: `pyproject.toml` and `uv.lock` pin `aws-cdk-lib` and the SDK; `.node-version` names the Node the CDK runs on (nvm layout under the home directory, or the absolute directory in `BIBLIOS_NODE_BIN`), which must report that version; `package.json` and `package-lock.json` pin the `aws-cdk` CLI, which `./bin/setup` installs under `.kickoff/infra-tools` through `./bin/check-infra --install` and which must report the pinned version. The check and the runner never provision: a missing or wrong piece is a refusal with no fallback.

`check_qualification.py` is the offline proof the full gate runs as `policy-infra`: it removes every AWS credential input from its environment (the sanitized environment is what keeps the SDK and the CDK CLI from reaching the account; the socket guard it loads binds the synthesizing Python process only), synthesizes all six stacks in-process, asserts each safety property on the real templates (no internet route in the private shape, the three Session Manager endpoints with private DNS, instance groups that admit nothing inline or through a standalone ingress rule, a private TLS-only bucket with no automatic object deletion, a run-scoped boundary (this run's inputs and results, Session Manager, the account reads, the one model when enabled; streaming, KMS, IAM and role assumption denied), a bounded and scoped role, IMDSv2 and no public address on the private instance, a disposable gp3 data volume whose `Encrypted` property is absent, ownership tags everywhere, no concrete identifier in any template), plants a mutant for each and requires the assertion to fail, synthesizes once more through the pinned CDK CLI with an external `--output` and requires the templates there and no `cdk.out` in the repository, then plants a context lookup and requires two specific refusals: in-process, the app declines a lookup for a stack with no account; through the CLI with a fictitious account, the CLI reports that it needs AWS calls but has no credentials. Run it directly from this directory, or through the wrapper:

```sh
./bin/check-infra
```

It does not establish live enforcement, endpoint availability, image contents, the account's boundary or any cost. Deployment is `bin/qualify-aws`'s job, one confirmation per step, described in the manual's AWS qualification chapter.
