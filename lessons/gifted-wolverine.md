span-recipe prints exact start argv only for native attempts; for a Codex critic reached through Folded the orchestrator started the intelligence span with category, operation and attempt only. record-role-dispatch then refused ('intelligence span role does not match registration'), acceptance validation requires exactly one closed intelligence span per attempt carrying harness, role, model and effort, and a closed span is immutable, so the trace could not be accepted. The critic had already run under the single-use owner exception, so that one extra review ended as a preserved report rather than accepted evidence. Remedies: the dispatch resource should state the non-native span recipe (read --harness/--role/--model/--effort from the registration file); the telemetry start command should refuse a role.* intelligence or wait span without role metadata so the defect fails before dispatch; and the orchestrator should open the span and verify its fields before launching any review that consumes an allowance.
