User-owned mirrors with per-entry isolation

Mirrors are the user's. Biblios re-indexes an edited mirror from its current bytes and never re-converts or rewrites it; one validated update operation is the supported edit seam. Replacing a file is a new ingestion: the new bytes are converted and the previous mirror, including an edit not yet indexed, moves to a retained name with a provenance record. Nothing on the ordinary path deletes mirror bytes; only explicit excision does. A mirror that is missing, has unparseable or incomplete YAML front matter, has invalid Unicode, or breaks a policy bound isolates only its own entry, never the shelf. Copies get their first mirror only from their own copy receipt.

Operator rulings recorded for this phase (relayed by the factotum with transcript evidence): "The mirror is never immutable." / "a mirror becoming actually corrupt should never block the entire shelf"; "Tower should never automatically re-convert a mirror."; "The only 'corruption' I can imagine are: - The mirror itself goes missing, - It's YAML metadata is unparseable or missing a required field, - The file contains invalid Unicode."; "Catching malformed updates should happen at the seam where users actually perform the updates."; "Replacing a file at a path is a new ingestion."; "The mirror is primarily associated with the bytes in the CAS, and only secondarily associated with the file path. Whether the replacement of a file results in a cumulative addition to the CAS or results in the excision of the previous bytes is a decision we should note for future enhancement but defer for now."
