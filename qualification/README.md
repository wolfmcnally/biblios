# qualification/ — the AWS qualification lanes, bundle and results

This directory is the qualification harness for one EC2 instance with the shelves on an EBS volume. It is not part of the `biblios` package and is never imported by it; it drives the product through the repository's own wrappers and the library's public calls.

- `lanes.py` runs on the instance through the staged checkout's interpreter (`./bin/python qualification/lanes.py`). It asserts every shelf root sits on the data volume, then runs the hermetic lane (the product suite with `--basetemp` on the volume and the three demos), the ingestion lane (the operator's corpus through Drawbridge, outcomes per kind; `incomplete` when `file`, Tesseract or Vellric is absent or a required document kind is missing from the corpus), the portability lane (seal, copy to a second directory on the same volume, open read-only, verify, search, then unseal the copy and prove it is rebuilt at its new root) and the Bedrock lane (one shelf through Palace's `bedrock` provider, `not-run` unless the settings declare `bedrock` with exactly the confirmed model and region, carry Palace's complete published-corpus assertion, and the confirmed text count covers its fixed input; `bedrock-settings.yaml` is the committed settings file for it; it passes only when Palace's reranker was applied to its search and its exported `bedrock-audit.jsonl` holds a successful retention check and an embedding request, which the runner's judge requires again from the retained artifact). It writes one JSON document the runner collects and exits nonzero unless every lane passed or was not run. `--allow-root-filesystem` exists only for local smokes and the container proof of the lane code and is recorded as a waiver.
- `audit.py` is the one home for the judgment three surfaces share about Palace's cloud-egress audit records (the Bedrock lane's verdict on the instance, the runner's judge on the retained artifact, the results renderer's wording): a complete audit holds at least one successful retention check and one embedding request; the records carry kind, status, model, dimension and timing, never text or a credential.
- `bundle.py build` produces, in a container of the instance's architecture, one archive of everything the instance needs with no internet: the checkout at the pinned commit, the managed Python runtime, `uv`, a cache pre-seeded by `uv sync --locked` for the product and for the Vellric sub-project, Palace's pinned reranker model (provisioned by `palace.rerank_model` into `models/`, reached through `PALACE_MODELS_DIR`) (`vellric/`, a locked project whose only dependency is the pinned Vellric release; the instance installs it offline from the cache and a `bin/vellric` shim names it), the corpus and, when supplied with `--tools <dir>`, prebuilt tool trees for the instance's distribution with a `bin/` shim per executable (git, which uv needs for its git-pinned sources; `file`; Tesseract built for Amazon Linux 2023, which does not package it), with a manifest of the archive's digest and every file's. `bundle.py prove` extracts that archive in a container of the instance's own distribution (Amazon Linux 2023 plus the archiver, built once from a recipe in `bundle.py`) with the network disabled, installs both environments from the staged cache and runs the hermetic and portability lanes through `lanes.py`, plus the ingestion lane when the bundle carries a corpus; the venue is the instance's distribution so that a host tool the bundle forgot fails the proof rather than the run. It is a prerequisite of the first deploy. `--source worktree` builds from the working tree for a development proof of the route; the runner refuses to stage such a bundle.
- `runner.py` is the program behind `./bin/qualify-aws`: `qualify` (deploy the five stacks including the CDK-written run-specific boundary, run, collect everything under the results prefix, tear down, in one invocation; a failure enters the scoped teardown of exactly the recorded stacks), `deploy --stacks` continuing from recorded state, `run --fixture/--fixture-command` for a foreign owner's archive and script, and the original verbs: `plan` (offline, in-process synthesis under a sanitized environment and a socket guard; no call of any kind), `deploy` (a read-only preflight behind its own confirmation that records the run's target, then one confirmation per stack naming what it creates, its parameters and its cost, with the created stacks recorded one by one), `run` (a disclosed identity check against the recorded target, then staging, the Bedrock binding and the Session Manager command, each confirmed; exit 3 unless the command succeeded and every requested lane passed), `results` (the sanitized brief) and `teardown` (identity check, a confirmed listing that retains any result artifact not yet local, removal of exactly the run's prefixes through every listing page, reverse destroy of the recorded stacks, tag-scoped inventory read back with every listed resource verified natively so stale index entries are named and live ones fail the teardown with exit 3; a bucket holding other objects is retained and reported). `--dry-run` renders every packet in order with placeholders and performs nothing. Every call goes through a transport the proofs can observe, and the journal records request parameters without bodies.
- `results.py` renders `briefs/aws-qualification-results.md` from the private evidence directory, with every identifier the run observed on a denylist and absent from the brief by construction.
- `cost-assumptions.json` holds the operator's hourly figures and their date; `corpus-manifest.yaml` records the corpus by kind and size only.

Evidence lives outside the tree under `QUALIFICATION_HOME` (default `~/.biblios-qualification/<run-id>/`): the journal of every call, the recorded target, the per-stack state, the command invocation, the lane records, log and exit status, the inventory and the denylist.
